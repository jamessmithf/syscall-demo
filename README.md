# Syscall Demo — Демонстрація системних викликів Linux

Два практичні приклади роботи з системними викликами Linux на C++:

- **Task 1** — читання пам'яті іншого процесу через `process_vm_readv` та `/proc/[pid]/mem`
- **Task 2** — перехоплення клавіатури через `/dev/input/` та інжекція синтетичних подій

## Вимоги

- Linux (Ubuntu / Debian / Arch або будь-який дистрибутив)
- g++ з підтримкою C++17
- `make`
- Для Task 2: права root (`sudo`) або членство в групі `input`

## Збірка

```bash
cd syscall_demo
make
```

Після збірки з'являться бінарники:
```
task1_proc_mem/target
task1_proc_mem/monitor
task2_kbd_hook/kbd_hook
task2_kbd_hook/inject_events
```

Очистити збірку:
```bash
make clean
```

## Task 1 — Читання пам'яті іншого процесу

### Що демонструє

- `process_vm_readv(2)` — читання VM-простору іншого процесу без ptrace
- `pread(2)` + `/proc/[pid]/mem` — резервний метод через псевдофайл ядра
- `prctl(PR_SET_PTRACER_ANY)` — дозвіл на читання власної пам'яті іншими процесами

### Як запустити

Потрібно **два термінали**.

**Термінал 1 — запусти цільовий процес:**

```bash
cd task1_proc_mem
./target
```

Програма виведе свій PID та адресу змінної:

```
=== TARGET PROCESS ===
PID              : 54321
&monitored_value : 0x601060
======================
Запустіть монітор:
  ./monitor 54321 0x601060

Введіть нове значення (Ctrl+C для виходу):
```

**Термінал 2 — запусти монітор з PID та адресою з Терміналу 1:**

```bash
cd task1_proc_mem
./monitor 54321 0x601060
```

Монітор починає опитувати пам'ять кожні 100 мс і виводить зміни:

```
=== MONITOR ===
Цільовий PID      : 54321
Адреса            : 0x601060
Інтервал опитування: 100 мс
Натисніть Ctrl+C для зупинки.
───────────────────────────────────────────
[init] початкове значення = 0
```

**Термінал 1 — вводь числа і спостерігай у Терміналі 2:**

```
Введіть нове значення (Ctrl+C для виходу): 42
[target] monitored_value = 42
```

Термінал 2 миттєво покаже:
```
[monitor] значення: 0 → 42
```

### Зупинка

- `Ctrl+C` у будь-якому з терміналів.

## Task 2 — Перехоплення клавіатури

### Що демонструє

- `read(2)` з `/dev/input/eventN` — читання всіх клавіатурних подій на рівні ядра, незалежно від активного вікна
- `ioctl(EVIOCGNAME)` — отримання назви пристрою
- `ioctl(EVIOCGBIT)` — перевірка підтримуваних типів подій
- `write(2)` до FIFO — інжекція синтетичних `input_event` для тестування без фізичної клавіатури

### Варіант А — реальна клавіатура (потрібен sudo)

**Термінал 1 — запусти перехоплювач:**

```bash
cd task2_kbd_hook
sudo ./kbd_hook
```

Програма автоматично знайде клавіатуру:

```
╔════════════════════════════════════════════╗
║        KEYBOARD HOOK via /dev/input/       ║
╚════════════════════════════════════════════╝
Пристрій : /dev/input/event3
Назва    : AT Translated Set 2 keyboard
Набирайте текст у будь-якому вікні.
Ctrl+C — зупинити.
────────────────────────────────────────────
```

**Термінал 2 (або будь-яке вікно) — набирай будь-який текст.**

У Терміналі 1 з'явиться:

```
  KEY [ 16] q
  KEY [ 17] w
  KEY [ 18] e
  KEY [ 57] SPACE
  KEY [ 28] ↵ ENTER
```

Вказати пристрій вручну:

```bash
sudo ./kbd_hook /dev/input/event3
```

Знайти свою клавіатуру:

```bash
ls /dev/input/by-id/
# або
cat /proc/bus/input/devices
```

### Варіант Б — тест через FIFO (без sudo, без фізичної клавіатури)

Цей варіант дозволяє протестувати перехоплення без реального пристрою.

**Термінал 1 — створи FIFO та запусти перехоплювач:**

```bash
cd task2_kbd_hook
mkfifo /tmp/fake_kbd
./kbd_hook /tmp/fake_kbd
```

**Термінал 2 — запусти інжектор:**

```bash
cd task2_kbd_hook
./inject_events /tmp/fake_kbd
```

У Терміналі 1 з'явиться симульований ввід тексту `hello World`:

```
  KEY [ 35] h
  KEY [ 18] e
  KEY [ 38] l
  KEY [ 38] l
  KEY [ 24] o
  KEY [ 57] SPACE
  KEY [ 42] SHIFT_L
  KEY [ 17] W
  KEY [ 24] o
  KEY [ 19] r
  KEY [ 38] l
  KEY [ 32] d
  KEY [ 28] ↵ ENTER
```

Після цього інжектор надсилає `Ctrl+C` і обидва процеси завершуються.

### Зупинка

- `Ctrl+C` у терміналі з `kbd_hook`.

## Системні виклики, що використовуються

| Виклик | Де використовується |
|---|---|
| `getpid(2)` | target — отримати власний PID |
| `prctl(2)` | target — дозволити читання пам'яті |
| `process_vm_readv(2)` | monitor — читання VM-простору процесу |
| `open(2)`, `pread(2)`, `close(2)` | monitor — читання через /proc/[pid]/mem |
| `read(2)` | kbd_hook — читання input_event з пристрою |
| `write(2)` | inject_events — запис синтетичних подій |
| `ioctl(2)` | kbd_hook — EVIOCGNAME, EVIOCGBIT |
| `usleep(3)` | monitor, inject_events — затримки між опитуваннями |
